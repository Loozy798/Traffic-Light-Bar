# Traffic Light Bar 完善设计

用户已选择直接按“弹窗＋详细仪表盘”方向完成，沿用原生 SwiftUI / AppKit，最低 macOS 15.6，不引入第三方依赖。

## 目标
- 状态栏保留红绿灯，可选择显示 CPU、内存或上下行速度。
- 弹窗提供系统状态、CPU / 内存占用、容量、网络、电池和高 CPU 进程摘要。
- 仪表盘提供最近五分钟趋势、CPU / 内存进程排行与搜索，独立设置窗口管理显示项、采样频率、提醒阈值和登录启动。
- 支持浅色 / 深色、键盘、辅助功能与最小窗口尺寸。

## 数据正确性和生命周期
- CPU 使用相邻 ticks 差值，首次采样显示等待；计入 nice ticks。
- 网络只统计物理网络接口，按网卡计算差值；新接口、计数回退、长采样间隔不产生假峰值。IP 与接口状态匹配。
- 内存展示占用、压缩、交换与系统内存压力；磁盘容量不参与性能评分。
- 红绿灯统一由 CPU、系统内存压力和温控状态的最高级别决定（CPU 50% / 80%）；尚无有效采样时显示等待。
- 电池通过 IOPSGetPowerSourceDescription 读取，按当前 / 最大容量计算；插电和充电分别显示。
- 系统采样由串行 utility 队列完成，发布到主线程；睡眠停止、唤醒重置基线，旧任务结果不覆盖新结果。
- 进程仅在界面可见或需要提醒时采样，每五秒一次；稳定 PID 标识，保留名称空格。读取管道后再等待退出，避免死锁。
- 用户在实机确认沙盒会拦截进程读取后，已明确授权关闭本 app 的 App Sandbox，启用完整进程监控；保留 Hardened Runtime。访问失败仍明确显示不可用及活动监视器入口，不能把失败显示为“系统正常”。不冒充真实能耗测量。
- 趋势保留五分钟有界历史；暂停与睡眠期间不伪造数据。

## 方案取舍
1. 仅精简弹窗：体积小，但无法分析持续变化和进程来源。
2. 弹窗＋仪表盘：用户选择；日常查看简洁，详情按需展开。
3. 常驻悬浮窗：额外占屏，与现有状态栏定位不符。
